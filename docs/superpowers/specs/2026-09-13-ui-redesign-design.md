# Редизайн UI/UX Launch Lab 21 — дизайн

Дата: 2026-09-13
Статус: одобрен пользователем

## Цель

Сделать интерфейс современным, узнаваемым и понятным без объяснений. Жюри турнира в первую очередь оценивает user flow, поэтому главная идея PDF («документ собирается сам из ответов») должна быть видна прямо во время ввода. Все требования PDF и текущая логика сохраняются.

## Решения

| Вопрос | Решение |
|---|---|
| Визуальное направление | Бренд Launch Lab 21: тёмно-синий фон, градиент фиолетовый → зелёный, как в PDF турнира |
| Экран модуля | Split-screen: слева форма, справа живое превью one-pager |
| Вход в роли | Стартовый экран с выбором «Я из команды» / «Я куратор»; переключатель в шапке остаётся |
| Реализация | Вариант А: переписать CSS и разметку экранов внутри `index.html`, логику не менять |

Отклонено: разделение на несколько файлов (нет выгоды для жюри); Tailwind и другие CDN (нарушают требование «без интернета»).

## 1. Визуальная система

**Цвета (CSS-переменные)**
- Фон приложения `--bg: #141925`, карточки `--surface: #1e2433`, приподнятые элементы `--surface-2: #262d3f`, границы `--line: #2f3749`.
- Текст `--ink: #eef0f5`, вторичный текст `--muted: #9aa3b5` (контраст не ниже 4.5:1 на `--surface`).
- Бренд `--violet: #8b3cf7`, `--green: #3ee89a`, градиент `--brand: linear-gradient(90deg, #8b3cf7, #3ee89a)`.
- Статусы: пройден — `--green`; текущий — `--violet` со свечением; частично — `--amber: #f5b544`; впереди — `--muted`; ошибка — `--red: #ff6b6b`.
- One-pager — светлый «лист»: фон `#ffffff`, текст `#1b1d22`. Цвета листа заданы отдельно, чтобы печать в PDF была чистой.

**Типографика**
- Системный стек шрифтов (без загрузки из интернета).
- Заголовок экрана 32–40px, заголовок карточки 20–22px, основной текст 17px, подписи не меньше 14px.

**Формы и компоненты**
- Скругления 14px у карточек, 10px у кнопок и полей.
- Главная кнопка — градиент бренда с тёмным текстом; вторичная — прозрачная с границей.
- Видимый фокус у всех интерактивных элементов (обводка `--violet`).

**Движение**
- Появление экранов (fade + сдвиг 8px, 200мс), заполнение прогресса, вспышка сохранённого раздела, мягкая подсветка обновляемого раздела в превью.
- `@media (prefers-reduced-motion: reduce)` отключает анимации.

## 2. Экраны и user flow

### 2.1 Старт (`#/start`, первый экран без выбранной роли)
- Hero: слоган «От сырой идеи до one-pager», подзаголовок одной фразой о платформе.
- Три шага «как это работает»: Модули → Ответы → One-pager.
- Две крупные карточки: «Я из команды» (роль участник) и «Я куратор» (роль куратор). Клик сохраняет роль и флаг `onboarded: true` в сессию и ведёт на экран роли (`#/` или `#/curator`).
- Правило маршрута: если `onboarded` не установлен, адреса `#/` и `#/curator` перенаправляют на `#/start`. Прямые ссылки на проект (`#/p/...`) работают по обычным правам доступа и старт не показывают.
- Переключатель ролей в шапке тоже устанавливает `onboarded: true`.
- Логотип в шапке всегда ведёт на `#/start`; стартовый экран доступен и после онбординга.

### 2.2 Участник: выбор проекта (`#/`)
- Карточка «+ Создать проект» и список проектов для выбора (название и состав команды, без чужого прогресса и ответов).
- Создание → профиль. Выбор → страница проекта. Ссылка «Сбросить демо-данные» внизу.

### 2.3 Профиль (`#/p/:id/profile`)
- Компактная форма из трёх полей. Для нового проекта кнопка «Сохранить и перейти к модулю 1 →».

### 2.4 Страница проекта (`#/p/:id`)
- Левая колонка: кольцевой индикатор прогресса (SVG, «N из 3»), текст «Осталось: …», главная кнопка «Продолжить: <модуль> →», кнопки «Профиль», «Сменить команду», «Открыть one-pager».
- Правая колонка: вертикальная дорожка модулей. Узел ✓ (пройден, зелёный), ● (текущий, фиолетовое свечение), ○ (впереди). У модуля: название, описание, бейдж статуса, бейдж 💬 N.
- Полоса сценария «Создать или открыть проект → Пройти модуль → Сохранить ответ → Увидеть в one-pager» сохраняется над контентом, в новом стиле.

### 2.5 Модуль (`#/p/:id/m/:moduleId`) — главный экран демо
- Сверху: полоса сценария и ряд шагов модулей.
- Левая панель (форма): «Модуль N из 3», название, описание, поля с подсказками, счётчик «Заполнено 2 из 3», блок комментариев куратора. Панель действий закреплена внизу: «Сохранить ответ и открыть one-pager →», «Отмена».
- Правая панель (живое превью): уменьшенный one-pager проекта (шапка профиля и все разделы модулей). При каждом `input` текст поля сразу появляется в разделе текущего модуля, раздел подсвечен. Над превью бейдж «Черновик · не сохранено» (после первого ввода) либо «Сохранено» (без изменений). Остальные модули показаны из сохранённых данных; незаполненные — как «Пустой раздел».
- Превью только отображает черновик и ничего не пишет в localStorage. Сохранение, как и раньше, происходит только по кнопке.
- При ширине меньше 1000px превью уходит под форму.
- Для куратора поля только для чтения, превью показывает сохранённые данные, кнопки сохранения нет.

### 2.6 One-pager (`#/p/:id/onepager[/:savedModuleId]`)
- Панель действий: «← К модулям» (или «← Все команды» для куратора), индикатор «Готовность N из 3», «Печать / PDF».
- Баннер «✓ Ответ сохранён» с кнопкой «Следующий модуль» или «Дозаполнить модуль», как сейчас.
- Светлый лист: обложка (метка One-pager · Launch Lab 21, название, описание, команда, полоса готовности), разделы-карточки по модулям. Пустой раздел — пунктирная рамка с текстом «Пустой раздел». Сохранённый раздел подсвечен.
- Комментарии куратора под разделами (не печатаются).

### 2.7 Куратор (`#/curator`)
- Заголовок «Режим куратора», четыре карточки статистики: команд, средний прогресс, прошли программу, комментариев.
- Таблица команд: название и состав, мини-прогресс, точки модулей, текущий модуль, дата обновления, 💬 N. Клик по строке открывает one-pager команды. На узком экране таблица прокручивается внутри своего контейнера.

### 2.8 Шапка
- Логотип с градиентной «21», хлебные крошки, переключатель ролей (сегментированный контрол, заметный на тёмном фоне).

## 3. Что не меняется

- Данные: `MODULES`, `PROFILE_FIELDS`, `seedState`, ключи `ll21.state.v2` и `ll21.session.v1` (к сессии добавляется только `onboarded`).
- Функции прогресса и статусов, комментарии, права доступа участника и куратора, роутер на hash, защита несохранённых изменений, экранирование пользовательского ввода.
- Один файл `index.html`, без внешних ресурсов, запуск двойным кликом.

## 4. Ошибки и крайние случаи

- Пустая форма модуля: сообщение «Заполните хотя бы одно поле» рядом с кнопкой (как сейчас).
- Длинный текст ответа не ломает превью и лист: `overflow-wrap: anywhere`, `white-space: pre-wrap`.
- Проект без названия и описания: в обложке «Название не указано» и «Описание не заполнено».
- Уход с черновиком из формы модуля или профиля: подтверждение (как сейчас).

- Три живые проверки PDF: перезагрузка сохраняет ответ; фраза жюри попадает в one-pager; пустой модуль показан как пустой раздел без поломки вёрстки.
